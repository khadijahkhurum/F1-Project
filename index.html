Problem Statement

Race-critical models weren't built to be attacked.

Formula 1 pit-wall software increasingly leans on ML to call strategy in real time. This project asks a question GRC frameworks are only starting to ask of ML systems: what happens when the telemetry feeding that model is quietly manipulated?

This research investigates the vulnerability of machine learning models used in Formula 1 telemetry-driven decision systems to adversarial manipulation, and evaluates robust training as a mitigation strategy.

Using public 2023-season telemetry accessed via the FastF1 library, the study targets a realistic operational task: predicting whether a car will pit within the next two laps, and measuring how small, malicious perturbations in telemetry data degrade model confidence and decision-making — the same failure mode that threatens any safety-critical, low-prevalence detection system, from race strategy to fraud and intrusion alerting.

No proprietary or restricted data is used — every lap in this study is public FastF1 telemetry from the 2023 season.

  • 01Model pit-stop likelihood from race telemetry features.
  • 02Simulate adversarial telemetry manipulation at controlled perturbation budgets.
  • 03Evaluate attack impact on model confidence, not just predicted class.
  • 04Implement and stress-test robust (noise-augmented) training as a defense.
  • 05Frame findings as a cybersecurity risk assessment, not just a modelling exercise.

Telemetry access

Smoke-tested the FastF1 client against live session data — lap times, sectors, tyre state, car telemetry — for three 2023 Grands Prix.

02

Dataset construction

Engineered lap-level features (sector times, tyre life, rolling lap-time mean/std) and labelled PitWithinNextNLaps across 2,586 laps.

Baseline model

Trained a class-balanced Random Forest on an 80/20 split and tuned the decision threshold for the rare pit-stop class.

04

Adversarial attack

Injected ±2% noise into test-set telemetry and re-scored the same model — no retraining, pure inference-time manipulation.

Can you fool the model — and can the defence stop you?

Every lap, an F1 car streams live telemetry — speed, throttle, brake, tyre wear — into a strategy model that predicts one thing: will this car pit in the next two laps? An adversarial perturbation is a small, deliberate change to that telemetry, designed to fool the model (here, ε = ±2% of each value).

Key Findings

What the numbers actually mean.

01

Accuracy hid the failure completely.

The baseline model held 99.4% accuracy both before and after the attack — because it almost never has to be right about the rare class to score well. Accuracy is the wrong instrument for a 0.5%-prevalence event.

02

A ±2% perturbation halved peak confidence.

Maximum predicted pit-stop probability fell from 17.3% → 9.75% under attack — an imperceptible telemetry shift with an outsized effect on the model's only useful signal.

03

Robust training works — up to a budget.

Noise-augmented training preserved detection at ε≤0.01 (F1 0.10–0.118), then collapsed to F1 0.0 at ε=0.02 and beyond, with predicted positives dropping from 17 to 3.

04

Defense is mitigation, not cure.

Robust training is a real, measurable improvement at small perturbations — and an honest limit past them. That residual risk, not a false "solved," is what a security assessment should report.
